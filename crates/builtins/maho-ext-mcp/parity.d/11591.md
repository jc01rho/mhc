# 11591 - legacy HTTP+SSE client transport (oh-my-openagent #11591)

oh-my-openagent #11591 routes an explicit `type: "sse"` skill MCP server to the MCP SDK's
`SSEClientTransport` (`@modelcontextprotocol/sdk/client/sse.js`). The SDK is not a senpi source
file, so this fragment has no `TS path` rows; the skill-manager side is ledgered in
`crates/omo/maho-omo/parity.d/11591.md`.

- `src/transport_sse.rs`: the endpoint rule (`new URL(data, streamUrl)` plus the origin check that
  refuses an endpoint on another origin) and an incremental `text/event-stream` decoder.
- `src/transport_sdk.rs`: `McpTransportSpec::Sse` and the `ClientTransport::Sse` arm. The first
  send opens the GET stream with the configured headers and the OAuth bearer; every message is
  POSTed to the announced endpoint with the negotiated `mcp-protocol-version`; replies, server
  requests and notifications arrive as `message` events and are routed like the stdio reader routes
  them. `close()` (or dropping the client) aborts the stream; pending requests then fail and later
  sends report `Not connected`, the error the skill manager reconnects on.
- Same-origin redirects only (`within_origin_client`), a safety divergence from the SDK.

Tests: `tests/sse_transport.rs` (initialize, tools/list and tools/call over a loopback 2024-11-05
server with the header and version checks; the request-budget timeout and the stream close; the
refused cross-origin endpoint; the rejected GET) and the unit tests in `src/transport_sse.rs`.
