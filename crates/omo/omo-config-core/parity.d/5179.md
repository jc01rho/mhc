## Notes

- `session_wake` and `device_service` are accepted at top level, in `[native]`/`[senpi]`/`[codex]`
  and in profiles; `device_service.enabled` defaults to `true` on the root view only, as upstream.
  Nothing in mhc consumes either key yet (the wake carrier and the device service bootstrap belong to
  the thread/remote tracks); `resolve_session_wake_settings` and `is_omo_device_service_enabled` are
  the readers those ports call.
- `memory.runtime` lands with upstream's defaults (7/14/30 days, 60 s pass budget, unreflected
  journals kept, 2 GiB cap) on the root block, optional in layers and `memory.agents.<id>`.
- `ModelDistributor` keeps its cursors behind a `Mutex` (one per planner, shared by its spawns);
  `PartialEq` is identity so option structs that carry it keep their derives.
- `task.parent_model_fallback` is a fork key (POL-01, omo #12010/#12761): optional in the root and
  layer task schemas; absent or `true` keeps mhc's parent-model fallback, `false` selects upstream's
  designated-chain-only behaviour.
- `assets/omo.schema.json` is not regenerated here: the generator (`tools/omo-schema.mjs
  --generate`) runs the `omo_schema` example through cargo, which this port does not run locally.
  The in-memory projection (`omo_config_json_schema`) already carries every key, and its tests run
  in CI.
