What landed:

- A revoke, sign-out or recovery-key removal freezes batch pushes (`stale_base`) until a member
  appends a rotation excluding the revoked principal. Any eligible member rotates, races on the
  sequencer, adopts the winner's rotation when it loses, and never rotates twice for the same head
  or revoked set. A push refused `stale_base` asks the settler first, and an unfinished settle shows
  as a `frozen` status instead of a silent `pushed: false` (#12280, #12302).
- Turning sync off on this device clears the service switch first and then leaves a local mark, so
  later sessions stay idle without asking the service; turning it on clears the mark (#14093).
- Recovery phrases are 32 bytes of entropy shown as 24 BIP39 English words, with keys derived by
  HKDF-SHA-256 bound to the account and the enrollment nonce. Neither a `Debug`/`Display` surface nor
  a parse refusal can carry a word, and the private halves zeroize (#13330).
- Phrase-key admission follows the contract: the reserved rp_id, the reserved `omo-sync/` namespace
  for passkeys, and a 16-byte phrase credential (#13330).
- Creating a phrase is fail-closed: the client flag defaults off and the service floor must read
  positively `on`; a wordless crash marker and an atomic intent store surround the ceremony
  (#13335).

The self-hostable server this track adds (`crates/maho-sync-server`) is original code, not a
translation, and has no row here.

## Salvage round (2026-11-22, `task/r2-sync-salvage`)

The two remote slice branches that PR #42 replaced left behaviour behind. This round ported the
scenarios that upstream states and `main` did not cover, and fixed what they exposed:

- `validate_bootstrap` now runs the shared `recovery_kind_of` rules, so a `phrase` key with a
  foreign rp_id (or a passkey rp_id inside the reserved `omo-sync/` namespace) can no longer be
  sealed as a first-device genesis (#13330 contract sec 1).
- PRF salt inputs exclude phrase keys and every reserved `omo-sync/` rp_id (contract F12) while the
  `MAX_RECOVERY_KEYS` bound still counts both kinds.
- The phrase floor read is time-bounded, so a stalled `/v1/sync/state` reads as `unknown` and
  refuses creation instead of hanging the ceremony.
- `TypedPhrase` and both parse normalizations hold their text in `Zeroizing`, and the redaction
  test now scans every word plus hex/base64/base64url encodings of the entropy and both private
  keys across `Debug`, `Display` and every refusal.
- `maho-sync-server`: `/v1/sync/entries` rows match `envelope::parse_entry` exactly (base_seq,
  account, full author keys, no object id on batch rows), keyring digests are JCS-canonical, the
  body limit admits the client's 8 MiB cap, uploads check size and digest, a repost answers before
  the freeze check, and `/v1/devices`, `/v1/confirm`, the pairing routes and
  `POST /v1/admin/devices/{id}/revoke` exist so `read_revocation_view`, `PairingHttp` and the
  freeze settler work against the server.
- The event-stream e2e test waits for `on_connected` before appending, so it cannot miss the head.
