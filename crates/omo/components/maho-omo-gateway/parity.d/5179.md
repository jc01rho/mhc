Partial rows and why:

- `drain.ts`: only the decision's expected turn now reaches the admission (upstream parity for #12921); the intake
  admission of rows from another device (#13037) belongs to the remote track.
- `addressing.ts`: the exact ladder (id, session id, NFKC name, unique id prefix, out-of-workspace `scope_denied`) and
  the git-work-tree workspace scope are ported; account aliases and fuzzy ranking stay with the send path and the
  remote track.
- `session-host.ts`: the `SessionHost` port and `SessionOpenRequest` are ported as the boundary; `createdThreadId`,
  `LocalSessionHost` and thread_create itself are not (thread_create needs the receiver admission mhc does not wire yet).
- `local-control.ts`: `waitSettled` (thread_read `wait_ms`) and `readEntryPage` (#14047 paged remote reads) are not
  ported; every other method is.
- `locate.ts`, `rename.ts`: the relay leg is the `RemoteControlLocator` hook; without an account alias registry an alias
  becomes the local name with `alias_scope: "local"`, `alias_unavailable: "no_remote"` (upstream's no-remote answer).
- `thread-state.ts`: `rowState` reads another device's listing row (remote track).
- `thread-row.ts`: `currentResult` replays receipts stored by an earlier build; the control tools record no receipts yet.
- `read-ops.ts`: `wait_ms` and entry-page cursors are not ported; tail reads, older-page cursors and the JSONL fallback
  are.
- `tools.ts`: thread_list, thread_read, thread_interrupt, thread_close, thread_rename, thread_set_model,
  thread_set_reasoning and thread_archive are added beside the existing send and handoff tools. thread_create, the
  receipts wrapper and the per-call deadline are not ported. This fragment's binding-tool rows are superseded: the
  send, handoff, report, outbox, outbox_ack, bind and bindings tools of this range were all removed by todo 5184c
  (`thread-core`), which is why this paragraph names no binding tool.

Native registration (`src/thread/native.rs`) registers `thread_send` only, and only with a device service. The
session-control tools need a host surface (`ThreadHost`); `LiveThreadSurface` implements it over the `RpcTransport`
seam, and the native component connects no socket transport yet, so it does not register them. The two-session QA
runs them over a faux host in `tests/thread_control_tests.rs`.
