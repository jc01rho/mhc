Steps added (same order and SQL as upstream): v11 `deliveries.wait_kind` (#13014); v12 the intake ledger columns and
their partial unique index (#13037); v13 `woken_sessions` (#13037); v14 `session_wait`, `wake_counts`, `intake_marks`
and `intake_commands` (#13037); v15 the `deliveries` rebuild whose `mode_effective` CHECK takes `start` (#14333);
v16 `deliveries.collapse_key` (#14428). `GATEWAY_TABLE_REBUILDS` replaces `GATEWAY_NEEDS_FK_OFF` so a rebuild step
runs with `foreign_keys` OFF and its `pragma_foreign_key_check` is scoped to the table it rebuilt, not to `bindings`.

Reader floor (#14382): `GATEWAY_READER_FLOORS` mirrors upstream (`.., 13, 14, 14, 14`), every migration step writes
`gateway_meta.reader_floor` inside the transaction that bumps the version, and `schema_version` admits a newer store
only when the stored floor is a plain positive integer this binary meets. Malformed floors (empty, padded, exponent,
fractional, zero, negative, no `gateway_meta`) fail closed.

Not ported here: no mhc code writes or reads the v12..v14 tables yet (the woken-session registry, the intake ledger
and the stored session waits are the thread-wake track's behaviour; only their storage contract lands here), and
`collapse_key` is not offered on `thread_send` (the parameter belongs to the thread tools' argument schema).
