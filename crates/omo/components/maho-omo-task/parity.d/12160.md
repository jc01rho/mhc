# 12160 - finished team members leave the task widget (omo #12160, merge a3013e19d0)

Source: oh-my-openagent `a3013e19d0` (`packages/omo-senpi/src/components/task/`) and the test rename
`64a2e599a3` (#12571), after the v5.1.52 pin.

omo #12160 removed the carve-out that kept a completed team member in the below-editor task widget
while its handle stayed resident: `selectWidgetRecords` no longer takes `residentTaskIds`,
`StatusUiManager` lost `residentTaskIds`, and `backgroundWidgetRows` no longer renders completed rows.

The native row builders already select the non-terminal records only: `status_row_format::build_widget_rows`
and `background_widget_rows` filter on `is_terminal`, and `status_ui::StatusUiManager` has no
resident-handle seam. `TaskStatusUi` publishes the footer count and always clears the widget slot. No
production change was needed, so this fragment records the finding and the tests that now pin it.

- `tests/adapters.rs::finished_team_members_leave_the_widget_beside_a_running_one` ports the
  `buildWidgetRows` case "completed records beside a running record" (#12160, renamed by #12571) and
  runs it through both row builders.
- `tests/status_ui.rs::a_completed_team_member_leaves_the_background_surface` ports the two `status-ui`
  cases (the widget clears, no refresh timer runs) against the footer and the widget slot.

The TS cases that hand `residentTaskIds` a resident id have no Rust counterpart because that seam does
not exist here. `/tasks` listing and `task_send` revival are unchanged.
