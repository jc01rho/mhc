The prelude JavaScript is upstream's, byte for byte. The tests run it in Bun, the eval kernel's
runtime: against stand-in `process` objects like upstream, and once against Bun's own `process`
(a cell-level `process.exit(3)` throws `ProcessExitInCell`, globals stay, and an exit bound before
the guard still ends the process).

The component registers after `ulw-loop`, as upstream's component list does.

Divergences:
- Upstream's tool description and prelude documentation carry the bunshin fleet SDK hint
  (`BUNSHIN_TS_CELL_HINT`). mhc ships no bunshin SDK (#12258 is not ported: the vendored SDK's
  license allows distribution only inside omo-ai and omo-senpi, and it needs the closed relay), so
  the description names the guard and the documentation keeps only the `process.exit` sentence.
- The prelude reaches a cell through senpi's eval-only prelude rule: an eval-exposed tool withheld
  from the model still contributes its prelude (senpi `reachableToolNames`). Until that codemode
  port lands, mhc installs the prelude only while the tool is active.
- mhc's worker and inline-worker kernel entries now bind `process.exit` before any cell runs and
  shut down through that binding (crates/maho-codemode/assets/UPSTREAM.json, status `patched`), so
  the guard cannot turn the worker's own exit into a throw; the process entry already did.
