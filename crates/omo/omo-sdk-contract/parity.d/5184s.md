The root's TypeScript type is computed from one table, `ROOT_CALLS`: each dotted key is one member, its input the static
type of its schema, its answer one of the three shapes of design 4.4, and `waits` whether it takes `CallOptions`. That
table is data, so it is carried as data here (`src/calls.rs`), with `inputAccepts` over every row (`validate.ts`) and the
answer records the contract directory declares itself (`src/results/root.rs`). The root object itself is slice P1b's.

Tests: `tests/root_calls.rs` (14 cases) over `src/calls.rs` and `src/results/root.rs`; the existing
`tests/contract_suite.rs` still covers the custody slice. The call table was checked against the pinned TypeBox schemas:
for all 134 rows, the table's `input_accepts` and TypeBox's `Value.Check` agreed on 4,398 generated probes (each row's
minimal sample, a sample with every optional field filled, and every single-field removal, retype and unknown-key
addition, nested), except 19 probes that name a JS handle (`api_key` on the five launch calls, `signal` on
`engine.schedule.run` and `threads.runToCompletion`): TypeBox types those `{}`, which admits any JSON value, while this
crate's earlier slice ruled a handle has no JSON form and keeps that ruling. The answer records agreed on their own
samples and field mutations.
