`resolve_request_timeout_ms` reads `timeout` from the raw skill MCP config `Value` and keeps only a
finite value in (0, 2^31-1] ms; anything else falls back to the native 30 s request budget (the TS
SDK default is 60 s). `request_timeout` feeds that budget to tools/resources/prompts list and to
call/read/get, with or without the caller's abort signal. `buildRequestOptions` has no separate
Rust form because the native client takes the timeout and the signal as separate arguments;
`a_call_carrying_an_abort_signal_still_times_out_at_the_configured_timeout` covers the pair.
The `claude-code-mcp-loader/types.ts` `timeout?: number` field is type-only in TS. The Rust skill
manager reads the raw `Value`, so `ClaudeCodeMcpServer` is unchanged: a strict `f64` field there
would make a non-numeric `timeout` fail the whole `.mcp.json` parse.
