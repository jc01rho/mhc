## The `thread_create` subsystem in mhc

`thread_create` was absent from mhc even at the v5.1.79 pin (`parity.d/5179.md`: "thread_create ... not ported"), so the rows above are the whole create, not only the v5.1.80..v5.1.83 delta. It is now registered (`src/thread/create_tool.rs`, from `tools.rs`) over one body (`src/thread/control/create.rs`) for a new, an existing or a forked thread on this device:

- placement and folder: `control/plan_create.rs` (`plan_create`, `existing_here`, `send_address_book`), `control/create_folder.rs` (a relative `cwd` and `~` resolve against the caller's folder), `worktree/{failures,thread_worktree}.rs` (typed folder failures, `check_folder`);
- launch checks: `control/create_launch.rs`, `contracts_permission_presets.rs` (a created thread's approval mode is the creator's or narrower), `initial_skills.rs`, `contracts_create_params.rs` (schema, shape checks, the refused-field naming);
- the open: `control/local_session_host.rs` (`LocalSessionHost`, `open_locally`, `workspace_note`), `control/session_host.rs` (`created_thread_id`, `opened_thread`), `control/open_reply.rs` (`model_refusal`), `ThreadHost::open_host_session` (default `unsupported:open_session`; `LiveThreadSurface` implements it over `open_session`);
- the first prompt: `control/prompt_start.rs`, `result.rs` `admitted_wait`, `thread_row.rs` `opened_result`, `errors.rs` (`prompt_not_started`, `gateway_schema_refusal`), `addressing.rs` `check_name_conflict`.

Tests (`crates/omo/components/maho-omo-gateway`): `tests/thread_create_tests.rs` (30 cases over a faux device and the registered tool through `LiveThreadSurface`; no sleeps, the sender and the start wait are scripted seams) and unit tests in the new modules. Upstream cases not carried: the device-b and relay-frame cases of `session-host.test.ts`, `thread-create-options.test.ts`, `thread-create-folder.test.ts`, `thread-create-device-name.test.ts`, `thread-create-no-primary.test.ts` and `thread-create-remote-unreachable.test.ts` (all need another device), `thread-create-worktree.test.ts`, and `local-thread-permission.test.ts` (below).

### Left out of the create, with the blocker

- **Another device, the account alias registry, `RelaySessionHost`, `plan-create.ts` `remote` branches, `remote/find-session.ts`:** no `RemoteThreadSurface` in `maho-omo-gateway` (thread-remote; the thread-address account surface is PR #87). `device` is refused `host_unavailable`; an alias is only the thread's local name (`alias_scope: "local"`, `alias_unavailable: "no_remote"`).
- **Worktrees:** `worktree/thread-worktree.ts` `createThreadWorktree`, `discard-worktree.ts`, `remote-worktree.ts`, `worktree-rpc*.ts` and the worktree branch of `local-open.ts` are not ported (older than the range; no row of it depends on them but `#14397`). A create that asks for one is refused `unsupported` (`details.reason = worktree_unsupported`) before anything opens.
- **Tool receipts:** see `#14665`; `create_tool.rs` passes no `retrying`.
- **Creator authority (#14045):** `EnqueueRequest` has no `authority`, so the first prompt reaches the new thread as a relayed message with the gateway header rather than as its own first message.
- **The creator's approval mode:** `ThreadToolsOptions` carries no permission preset (upstream reads it from the remote surface options), so `create_tool.rs` passes none: a `permission_preset` other than `ask` is refused `scope_denied`, and one left unset starts the thread in the host's default mode.
- **The receiving half (`create-receivers.ts`, `registerInitialSkills`, the `THREAD_WORKTREE_RPC` handler):** `skills` ride the `open_session` context (`initial_skills`) and are echoed as `requested_skills`, but mhc's own engine host does not read that key yet, so it applies none.
- **`tools/local-permission.ts` (`permissionParser`):** a `ThreadTool` has no permission-parser seam in mhc.
- **Delivery `device` on a wait:** a stored row carries no sender device (`Provenance` has none), so `waiting_on` names none.
