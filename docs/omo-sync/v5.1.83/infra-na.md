## Notes

- **Fork-owned surfaces untouched**: `.github/workflows/*`, `scripts/gh-verify.sh`, `scripts/gh-install.sh`, `AGENTS.md`, `CONTRIBUTING.md`, and `PINS.md` stay ours per the migration brief (hard rule 7 and lead pin bump at campaign end).
- **`assets/omo.schema.json`**: Only `keyword_detector` (#14389/#14392) and `operator_alerts` (#14430) were added in `v5.1.80..v5.1.83`. In `mhc`, `assets/omo.schema.json` is generated from `crates/omo/omo-config-core::omo_config_json_schema()` via `bun tools/omo-schema.mjs --generate` (which invokes cargo). Because `crates/omo/omo-config-core` (`misc-core`) does not declare `keyword_detector` or `operator_alerts` on `main` yet (and `maho-omo-ultrawork` / `maho-omo-gateway` run-alerts are handled by `ultrawork-skills` and `thread-wake`), updating `assets/omo.schema.json` here would introduce drift against `omo_config_json_schema()` and advertise keys stripped by `strip_unrecognized_keys`.
- **`docs/`**: `mhc` maintains Rust-oriented docs (`docs/cli.md`, `docs/configuration.md`, `docs/remote.md`, `docs/release.md`) rather than `docs/guide/*` or `docs/reference/*`. Each feature track updates `mhc`'s docs alongside the Rust implementation it ports.
