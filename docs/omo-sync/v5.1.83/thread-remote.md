## Baseline and scope split

1. **`maho-omo-remote`**: Uses `maho-thread-address-core` directly for `mhc remote` device resolution (`online: true`, NFKC names, `here`, 6+ char prefixes), `sessions --device` filtering (`online: false` + `unknownDevice`), `unanswered_devices` via `device_listing`, `row_name` / `row_key` / `unnamed` row metadata, bare session resolution, `listingNamedDevice` fallback, and `candidate_lines` (omitting candidates on `device_offline`).
2. **`maho-omo-gateway/src/thread/remote/`**: Keeps the `RemoteThreadPort` seam behind `with_remote_thread_tools` without colliding with sibling tracks (`thread-core`, `thread-control`, `thread-wake`). Adds `outcome.rs` and updates `device_service.rs` / `mod.rs` for `resolve_account_device`, `get_state` probe + `decide_delivery`, `effective_mode` (`start`/`steer`/`follow_up`), `auto` steer-race retry, `held` admission, `pair_loop_guard`, `collapse_key` unsupported refusal, and `here/` local fallthrough.
3. **Remaining `RemoteThreadSurface` live/create/monitor (`gap`)**: `listAcross`, `RemoteSessionsPort` extensions (`devices`, `this_device_name`, `session_command`, `closed`, `reopened`), `AliasRegistry::aliases_of`, `RelayControl` / `RelayControlLocator`, `closed-rows`, `attach-pool` and `reply_on_device` are now ported over the `RemoteThreadSurface` trait boundary; the live `DeviceServiceSessions` `mhc-relayd` adapter (`session.endpoints`/`session.locate`/`session.read` and `attach` event stream not yet served by `mhc-relayd`), `RelaySessionHost` remote `planCreate`, and `thread_monitor` remote watch source stay `gap`.
