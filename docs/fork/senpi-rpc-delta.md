# senpi RPC host delta ported by the snp-rpc track (SNP-03)

mhc ports senpi at the pin `59d58cee5` (v2026.10.27-2); the target is `6d4426a28` (v2026.11.19-5). The pin-to-target
delta of `packages/coding-agent/src/modes/rpc` is large (compact recovery catalogs, attach ledger, delegated
connections, method classes). This change ports the slice below and nothing else of it; each row names the senpi PR
(the merge commit on senpi `main`), what it changed, where it landed in mhc, and what was left out and why.

| oh-my-openagent#14313 (`UNLOAD_GRACEFUL_CAPABILITY`) | `unload_session { graceful: true, waitMs }`: the fence comes first (`holdForClose`, admission closed `session_closing`, queued input handed back unread), the turn and its tool calls end on their own inside `waitMs`, and a drain past its bound reopens the session as it was (`graceful_expired`) | none | not ported: it needs three session-layer pieces this port does not have - the closing hold (`holdForClose`/`releaseCloseHold`), the `session-closed` record written on request (`recordClosedOnRequest`), and the answer's `graceful: { turn, waited_ms, stopped }`. The drain itself (`drainUntilQuiet`) would map onto `AgentSession::subscribe` + `wait_for_idle`, but the close half cannot be faked without inventing those records, so the capability is not advertised. A client must check it before sending `graceful`: one that sends it anyway gets a plain unload (the unload path never reads the field), so a busy session is refused `turn_active` with nothing aborted, an idle one unloads, and the answer carries no `graceful` facts. A caller that closes with a bounded graceful wait depends on this capability |

## Follow-ups found while porting

- `AgentSession::clear_queue` never calls `external_admission().drop_queued()`, which senpi's `clearQueue` does at the
  pin. A release's `take_queued_input` therefore reports no `dropped.deliveries` for deliveries the clear removed, and
  their admissions stay pending. `take_queued_deliveries` does drop them.
- `AgentSessionRelease::effect_session()` is `None`, so an `effectId` unload is refused as `unsupported` on a real
  host; the `dropped` and `pending` effect fields are exercised through fakes only.
- `crates/maho-tool-child/src/rpc_socket.rs` keeps its own copy of the old truncate-and-write secret functions.
- `host_capabilities::multi_session_host_capabilities` is a port that the running host does not call; the host builds
  its list in `multi_session_host.rs` `advertised_capabilities`, where both new capabilities were added.
